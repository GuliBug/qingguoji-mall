## 一、后端集成测试用例（TC-01 ~ TC-12）

| 用例 | 对应规格 Scenario | 步骤摘要 | 预期结果 |
|---|---|---|---|
| TC-01 | 会员·登录（新用户/验证码错误） | 错误验证码登录→正确验证码登录→重复登录 | 错码拒绝；自动注册返回注册会员；同手机号同一会员 |
| TC-02 | 会员·签到（重复签到） | 签到→再签到 | 首次 +5 积分；再次报"今日已签到" |
| TC-03 | 会员·扫码积分（防重/日限20） | 用已核销码→连续扫 20 个新码→再扫第 21 个 | 已用码拒绝；+200 积分；第 21 个报"上限" |
| TC-04 | 会员·等级体系（银卡折扣倍率） | 成长值 6000（银卡）下单 ¥100 | 95 折优惠 5 元，95<99 加运费 8 → 实付 103；支付积分 103×1.5=155 |
| TC-05 | 库存·四原语（库存不足回滚） | 两行下单：A 库存足、B 超库存 | 整单失败；无订单产生；A 行预占随事务回滚 |
| TC-06 | 库存·并发防超卖（AC-01） | 可售 5 件，10 线程并发各下单 1 件 | 恰好成交 5 单；锁定=5；可售归零 |
| TC-07 | 订单·支付（幂等+扣减+发积分） | 下单 2×¥20 → 支付 → 重复支付 | PAID；库存 100→98 锁定归零；积分 48（含运费）；重复支付被拒 |
| TC-08 | 订单·超时取消（AC-02） | 下单 3 件→payDeadline 置过期→跑定时取消 | CANCELED；锁定释放归零；幂等重跑不变 |
| TC-09 | 售后·申请约束 | SHIPPED 订单申请仅退款；申请 5 件超可退 | 各被拒并提示规则文案 |
| TC-10 | 售后·退货退款全链路 | 申请→审核→填退货物流→确认收回 | WAIT_AUDIT→WAIT_RETURN→WAIT_RECEIVE→DONE；库存 100−2+1=99；积分 100→50（REFUND_BACK 流水） |
| TC-11 | 售后·仅退款完成 | PAID 订单仅退款 1 件→审核通过 | DONE；库存不回补（100−5=95）；积分扣回 10 |
| TC-12 | 订单·发货收货状态机 | WAIT_PAY 发货→支付→发货→收货→重复收货 | 各状态流转正确，非法流转被拒 |

## 二（增）、字段级校验测试用例（F01 ~ F12，每个字段逐值验证）

| 用例 | 接口 | 覆盖字段与取值 |
|---|---|---|
| F01 | 登录 | phone：null/空串/3位/非1开头(238...)/10位 → 均报"手机号格式不正确" |
| F02 | 登录 | smsCode：null/空白串 → "验证码不能为空"；错误值 → "验证码错误" |
| F03 | 加购 | skuId：null → "SKU 不能为空"；不存在(999999) → "SKU 不存在" |
| F04 | 加购 | qty：null/0/−1 → "必须大于 0"；1000 → "不能超过 999"；上边界 999 正常 |
| F05 | 购物车更新 | qty：null → "数量不能为空"；cartId 不存在 → "购物车项不存在"；qty=0 → 删除该行 |
| F06 | 下单 | receiver：null/空白 → "收货人不能为空"；phone：null/"12345" → "手机号格式"；address：空/null → "收货地址不能为空" |
| F07 | 下单 | lines：null/空数组 → "明细不能为空"；line.skuId null → "SKU 不能为空"；qty 0/−2 → "大于 0"；skuId 不存在 → "SKU 不存在"；qty 101 超库存 → "库存不足" |
| F08 | 扫码 | code：null/空串 → "不能为空"；不存在 → "防伪码不存在" |
| F09 | 售后 | type：EXCHANGE/null → "售后类型不合法"；reason：空/null → "请填写售后原因"；orderItemId 不存在 → "订单明细不存在" |
| F10 | 管理端·商品/库存 | status：null/2/−1 → "状态值不合法"；0/1 合法生效；delta：null → "不能为空"；0 → "不能为 0"；−999 超扣 → "库存不足"；+50 合法生效 |
| F11 | 管理端·积分/发货 | 积分 delta：null → "不能为空"；0 → "不能为 0"；+10/−10 合法（含负向扣减）；发货 logisticsNo：空/null → "物流单号不能为空"，合法值生效 |
| F12 | 管理端·登录 | 错用户名/错密码 → null + 失败响应；正确账号签发 token |

## 二（增2）、退货退款全链路与双端联调用例（E2E-36 ~ E2E-46，第三轮）

| 用例 | 端 | 覆盖链路 | 预期结果 |
|---|---|---|---|
| E2E-36 | H5 | 申请退货退款 | WAIT_AUDIT，退款额=明细实付 |
| E2E-37 | Web | 未寄回时确认收货 | 被拦截"售后单状态不允许确认收货" |
| E2E-38 | Web | 审核通过 | 状态 → WAIT_RETURN |
| E2E-39 | Web/H5 | 退货物流单号为空 | "退货物流单号不能为空"（第三轮发现的真实缺陷，已修复） |
| E2E-40 | H5 | 填写退货物流 | 状态 → WAIT_RECEIVE，my 列表可查 |
| E2E-41 | Web | 商家确认收货 | 状态 → DONE，退款完成 |
| E2E-42 | H5 | 退货回补库存 | 可售库存 +1（如 788 → 789） |
| E2E-43 | H5 | 积分按比例扣回 | 扣回 = round(支付积分 × 退款额 ÷ 实付) |
| E2E-44 | Web | 管理端页面（若依风格 admin.html） | 页面可达，商品/售后/会员模块齐全 |
| E2E-45 | H5 | 五个页面模块联调编译 | index/product/cart/orders/member 全部 200 |
| E2E-46 | H5↔后端 | api.ts 契约对账 | H5 前端 15 个接口全部被 E2E 真实执行，无契约漂移 |
