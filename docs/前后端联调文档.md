## 1. 联调环境

| 项 | 值 |
|---|---|
| 后端启动 | `cd backend && mvnw spring-boot:run`（需 unset `SERVER_PORT`/`SERVER__PORT` 环境变量） |
| 前端启动 | `cd frontend-h5/mall-client && npm run dev:h5`（或 `npx taro build --type h5 --watch`） |
| 数据库 | H2 内存库，重启即重置（种子数据自动重建） |
| 演示账号 | 买家：任意手机号 + 验证码 `123456`；管理端：`admin / admin123` |
| 鉴权方式 | 请求头 `X-Token`（登录接口返回，前端存 Storage） |

**前端 BASE 配置**：`src/api.ts` 的 `BASE = 'http://localhost:8080'`；后端已开 CORS（`CorsConfig`）允许 H5 端口跨域。

## 2. 联调接口对账表（前端 api.ts ↔ 后端 Controller）

| 前端方法 | 后端接口 | 联调要点 |
|---|---|---|
| `api.login(phone, smsCode)` | POST `/api/member/login` | 返回 `{token, member, levelName}`，前端须存 token |
| `api.me()` | GET `/api/member/me` | 未登录返回 code≠200，前端按未登录态渲染 |
| `api.checkin()` | POST `/api/member/checkin` | 重复签到返回「今日已签到」 |
| `api.scan(code)` | POST `/api/member/scan` | 错误分支：码不存在/已使用/超每日 20 包上限 |
| `api.products(page, category)` | GET `/api/products` | 按销量倒序；category 为空串则不筛 |
| `api.productDetail(id)` | GET `/api/products/{id}` | `skus[].totalStock − lockedStock` = 可售 |
| `api.addToCart(skuId, qty)` | POST `/api/cart` | 下架商品返回「商品已下架」 |
| `api.updateCart(cartId, qty)` | PUT `/api/cart/{cartId}` | qty=0 即删除该行 |
| `api.createOrder(lines, …)` | POST `/api/orders` | **核心联调点**：库存不足/下架/明细空各自有 msg；成功返回订单含 `payDeadline` |
| `api.pay(orderNo)` | POST `/api/orders/{orderNo}/pay` | 幂等：重复支付返回「状态不允许支付」 |
| `api.cancel(orderNo)` | POST `/api/orders/{orderNo}/cancel` | 超时单已被定时任务取消，幂等不报错 |
| `api.confirm(orderNo)` | POST `/api/orders/{orderNo}/confirm` | 仅 SHIPPED 可确认 |
| `api.orders(status)` | GET `/api/orders` | status 为空查全部 |
| `api.applyAfterSale(…)` | POST `/api/aftersale` | 已发货订单传 REFUND_ONLY 会被拒（仅支持退货退款） |
| `api.myAfterSales()` | GET `/api/aftersale/my` | WAIT_RETURN 状态需引导填退货物流（`/return-logistics`） |

## 3. 核心链路联调时序（参照 spec 5.2）

```
H5                     后端                        数据变化
│ POST /api/orders ───▶ lockStock 条件更新 ───▶ lockedStock ↑（可售 ↓）
│   返回 payDeadline     订单 WAIT_PAY
│ POST /pay ──────────▶ deductStock ──────────▶ totalStock ↓、lockedStock ↓
│                       状态 PAID、发积分/成长值
│ POST /api/aftersale ─▶ 校验数量/状态 ────────▶ orderItem.afterSaleQty ↑
│   （管理端审核通过）    finishRefund ─────────▶ 积分扣回（REFUND_BACK）、
│   RETURN_REFUND 回补库存 totalStock ↑
│ 15 分钟未支付 ───────▶ Scheduler 批量取消 ──▶ lockedStock 释放、CANCELED
```

## 4. 联调冒烟用例（已跑通 ✅）

| # | 用例 | 步骤 | 预期 |
|---|---|---|---|
| 1 | 登录 | 手机号 13800001111 + 123456 | 返回 token，等级"注册会员" |
| 2 | 加购下单 | 商品 2 首个 SKU × 5 | 实付 = 单价×5，<99 加运费 8 |
| 3 | 支付 | `POST /pay` | 状态 PAID，积分 +实付×1.0 |
| 4 | 库存核对 | 再查详情 | totalStock −5，lockedStock 归 0 |
| 5 | 仅退款 1 包 | 明细 REFUND_ONLY qty=1 | 退款金额 = 单价，状态 WAIT_AUDIT |
| 6 | 管理端审核 | admin 登录 → audit pass | 售后 DONE，积分按比例扣回 |
| 7 | 异常分支 | 复扫已用防伪码 / 超库存下单 | 各自返回明确 msg，数据不变 |

## 5. 常见联调问题（FAQ）

| 现象 | 原因 | 解决 |
|---|---|---|
| 后端起在随机端口 | 宿主环境变量 `SERVER__PORT` 被 Spring 松散绑定 | 启动前 `unset SERVER__PORT SERVER_PORT` |
| 前端请求跨域失败 | 后端未启动或 CORS 未生效 | 确认 :8080 存活；检查 `CorsConfig` |
| 接口 401/无权限 | `X-Token` 未带或 admin token 访问 /api | 前端确认已登录；两套 token 不可混用 |
| 数据"莫名其妙变了" | H2 内存库重启重置 + 种子数据重建 | 属预期，联调前先重新登录拿新 token |
| 支付成功但列表还是待付款 | 页面未刷新 | 支付成功回调里刷新订单列表 |
| 售后数量校验失败 | 累计售后数超明细 qty | 以前端展示的"最多可退 N 件"为准 |

## 6. 联调验收标准（对齐 spec AC）

- AC-01 防超卖：并发下单仅允许成交 ≤ 可售数量；
- AC-02 超时取消：15 分钟未支付自动 CANCELED 且库存释放；
- AC-05/AC-12 售后约束与积分扣回数值正确；
- AC-09/AC-10 签到/扫码积分与防重防超限生效；
- 全部页面操作产生的数据变化可在 H2 控制台核对。
