## 2. 后端测试（JUnit5，26 例）

命令：`mvn test`（依赖 H2 内存库，无需外部 MySQL）。

### 2.1 业务链路集成测试 `MallFlowIntegrationTest`（12 例）
覆盖完整业务闭环，使用真实 HTTP 端口（随机端口 + TestRestTemplate）：

| 场景 | 验证点 |
|---|---|
| 会员登录 | 正确验证码返回 token；错误验证码返回 401 |
| 商品列表/详情 | 返回种子商品、SKU 价格与库存 |
| 加购 | 添加购物车项，库存预占 |
| 下单 | 创建订单，金额 = 商品价×数量 + 运费（满 99 包邮） |
| 支付 | 状态 PENDING→PAID，发放积分 |
| 取消订单 | 状态→CANCELED，库存释放 |
| 确认收货 | PAID→SHIPPED→COMPLETED |
| 申请售后 | REFUND_ONLY / RETURN_REFUND 两类 |
| 签到 | 连续签到累计奖励（+5，断签重置） |
| 扫码 | 有效防伪码 +10 积分；无效码报错 |
| 管理端登录 | admin/admin123 返回 token |
| 管理端鉴权 | 无 token 访问 dashboard 返回 401 |

### 2.2 字段校验测试 `FieldValidationTest`（13 例）
校验入参非法时的 `ServiceException` 文案与状态码：

- 加购数量 ≤ 0 / 超过库存上限
- 下单收货信息缺失、商品不存在、库存不足
- 支付/取消非本人订单、重复支付
- 售后数量 ≤ 0 / 超过可售后数量 / 类型非法
- 积分调整负数、会员不存在

### 2.3 上下文测试 `QingguojiMallApplicationTests`（1 例）
`contextLoads`：Spring 容器正常装配（无 Bean 冲突、无循环依赖）。

> 反例价值：后端重构（若依分层）后，这 26 例是「没改坏接口契约」的直接证据 ——
> 尤其验证了 `/api/**` 仍返回 `Page` 结构、`/admin-api/**` 返回 `TableDataInfo`、错误文案不变。

## 3. Web 管理端单元测试（Vitest，27 例）

命令：`npm run test:unit`（或 `npx vitest run`）。

| 模块 | 覆盖点 |
|---|---|
| `utils/request.spec.js` | axios 实例 baseURL、拦截器加 `X-Token`、401 清 token 重登、响应 `code` 分发 |
| `utils/format.spec.js` | 金额格式化、日期时间格式化、状态/枚举中文映射 |
| `utils/validate.spec.js` | 手机号、必填项、数字范围校验函数 |
| `utils/dict.spec.js` | 字典映射（订单状态、售后类型、会员等级） |

## 4. Web 管理端端到端测试（Puppeteer，10 例）

命令：`npm run test:e2e`（需先 `npm run dev` 起 5173，且后端 8080 在线）。

| 用例 | 验证点 |
|---|---|
| 登录页渲染 | 标题与默认账号提示可见 |
| 错误登录 | 错误密码停留登录页并提示 |
| 登录成功 | 跳转看板，渲染六个统计卡片 |
| 路由守卫 | 未登录访问受保护路由 → 重定向登录页 |
| 菜单渲染 | 侧边栏六个业务菜单 |
| 菜单跳转 | 点击菜单跳转对应路由 |
| 商品页 | 加载种子数据，SKU 聚合出价格区间 |
| 库存页 | 可售库存 = 总库存 − 锁定库存 |
| 订单/售后/会员页 | 均可打开且表格渲染正常 |
| 退出登录 | 回登录页并清除 token |

> 反例价值：E2E 在后端重构后用**真实浏览器**跑完整链路，
> 证明前端零改动即兼容新后端（管理端 `TableDataInfo` 与前端 `unwrapPage` 双兼容生效）。

## 6. 覆盖率与未覆盖项

- 后端：业务主链路覆盖较好；**未覆盖**定时任务 `OrderTimeoutTask`（订单超时取消，需时间注入）、H2 控制台关闭逻辑。
- Web：组件交互（如弹窗表单提交）以 E2E 覆盖为主，单元层聚焦纯函数。
- H5：**暂无自动化测试**（仅生产构建验证）；建议后续补 Taro 组件测试 + 小程序端 E2E。
- 安全：token 存内存、`DEMO_DATA` 开关等已在部署文档标注为「演示级」，未做安全渗透测试。
