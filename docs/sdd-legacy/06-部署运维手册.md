# 06 · 部署运维手册

> 完整版见 `docs/DEPLOY.md`。本章为 SDD 内的精炼索引，确保「设计→部署」可追溯。
> 两种方案均**已实跑验证**（含 `dist/app.jar` 独立运行、Nginx 反代配置、Docker Compose）。

---

## 1. 架构与端口规划

```
                ┌─────────────── 公网 80 ───────────────┐
  浏览器 ──────► │  Nginx                                │
                │   ├─ /        → Web 管理端 (127.0.0.1:5173 静态) │
                │   ├─ /h5/     → H5 客户端  (127.0.0.1:10086 静态) │
                │   └─ /api/ /admin-api/ → 后端 (127.0.0.1:8080)   │
                └────────────────────────────────────────┘
                                   │
                          后端 8080（仅绑 127.0.0.1）
                                   │
                          MySQL（生产）/ H2（演示）
```

| 组件 | 端口 | 对外 | 说明 |
|---|---|---|---|
| Nginx | 80 | 是 | 唯一入口，反代 + 静态托管 |
| 后端 | 8080 | 否（仅本机） | Spring Boot，jar 运行 |
| Web 管理端 | 5173 | 否 | 纯静态，由 Nginx 托管 |
| H5 客户端 | 10086 | 否 | 纯静态，由 Nginx 托管 |
| MySQL | 3306 | 否 | 生产数据源 |

## 2. 环境变量（生产通过 env 注入，不改 jar）

| 变量 | 默认值 | 说明 |
|---|---|---|
| `SERVER_PORT` | 8080 | 后端监听端口 |
| `SPRING_PROFILES_ACTIVE` | h2 | 生产改 `mysql` |
| `DB_HOST / DB_NAME / DB_USERNAME / DB_PASSWORD` | localhost / qingguoji_mall / root / root | MySQL 连接 |
| `DEMO_DATA` | true | 生产设 `false` 关闭演示种子数据 |
| `H2_CONSOLE` | true | 生产设 `false` 关闭 H2 控制台 |

---

## 3. 方案一：传统部署（systemd + Nginx）

```bash
# 1) 本机产出 dist/
cd qingguoji-mall && deploy\build.cmd
# 产物：dist/app.jar、dist/web/、dist/h5/

# 2) 上传并建库
scp -r dist/* user@server:/opt/qingguoji/
mysql -uroot -p < deploy/mysql/init.sql          # 建库 + 初始管理员 admin/admin123

# 3) 后端以服务运行
sudo cp deploy/qingguoji-mall.service /etc/systemd/system/
sudo systemctl enable --now qingguoji-mall

# 4) Nginx 反代
sudo cp deploy/nginx/qingguoji.conf /etc/nginx/conf.d/
sudo nginx -t && sudo systemctl reload nginx
```

`qingguoji-mall.service` 关键：以非 root 用户运行、失败自动重启、`Environment=SPRING_PROFILES_ACTIVE=mysql`。

---

## 4. 方案二：Docker Compose（推荐）

```bash
cd deploy
cp .env.example .env      # 按需修改 DB_*/DEMO_DATA/H2_CONSOLE
docker compose up -d --build
```

包含服务：`backend`（Dockerfile.backend，多阶段构建 jar）、`web` + `h5`（nginx 托管静态）、`nginx`（对外 80 反代）、`mysql`（挂载 init.sql 初始化）。

## 5. 运维检查清单

- [ ] 上线必须 `SPRING_PROFILES_ACTIVE=mysql`，否则 H2 内存库重启数据全丢。
- [ ] `DEMO_DATA=false`、`H2_CONSOLE=false` 在生产关闭。
- [ ] 后端只绑 `127.0.0.1`，禁止直接暴露 8080 到公网。
- [ ] 修改数据库密码后同步更新 `.env` 与 systemd 的 `Environment`。
- [ ] 健康检查：`GET /actuator/health` 应返回 `{"status":"UP"}`。
- [ ] 日志：`journalctl -u qingguoji-mall -f`（systemd）或 `docker compose logs -f backend`。

## 6. 已知生产限制（务必知悉）

1. **Token 存进程内存**：重启后端后所有用户需重新登录；多实例部署会串号，需改 JWT。
2. **演示登录**：H5 首页硬编码自动登录、购物车收件人硬编码（见《04-H5详细设计》第 3/4.3 节），上线前必须改造。
3. **H5 包体偏大**：`common.js` ~21MB（gzip 15.9MB），首屏慢，需 chunk 拆分。
4. **无 Redis**：原 pom 依赖 Redis 但代码零使用，当前未启用，限流/会话共享需后续补齐。
