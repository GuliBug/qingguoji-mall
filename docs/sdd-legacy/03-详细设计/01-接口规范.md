## 1. 通用约定

### 1.1 响应结构

所有接口统一返回：

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {}
}
```

| 字段 | 类型 | 说明 |
|---|---|---|
| `code` | int | `200` 成功 · `400` 业务/参数校验失败 · `401` 未登录 · `500` 系统异常 |
| `msg` | string | 面向用户的提示文案，前端可直接 toast |
| `data` | any | 业务数据，无返回值时为 `null` |

分页接口的 `data` 结构分两种（设计决策见 02 文档 ADR-05）：

```jsonc
// 客户端 /api/**：Spring Data Page
{ "content": [...], "totalElements": 42, "totalPages": 5, "number": 0, "size": 10 }

// 管理端 /admin-api/**：若依 TableDataInfo
{ "total": 42, "rows": [...] }
```

### 1.2 鉴权

| 项 | 说明 |
|---|---|
| 请求头 | `X-Token: <token>` |
| 令牌前缀 | 会员 `MBR-` · 管理员 `ADM-` |
| 校验方式 | 拦截器按 `@RequireLogin(LoginType.MEMBER / ADMIN)` 校验，未标注的接口公开 |
| 失败响应 | **HTTP 200** + `{"code":401,"msg":"请先登录"}` |
| 过期策略 | 演示环境无过期，服务重启后全部失效 |

两套令牌互不通用：用会员令牌调管理端接口同样返回 401。

### 1.3 其他约定

| 项 | 约定 |
|---|---|
| 请求体格式 | `Content-Type: application/json` |
| 时间字段 | ISO-8601 字符串，含微秒，如 `2026-10-22T11:12:47.123456` |
| 金额字段 | `decimal`，服务端保留 2 位小数 |
| 分页参数 | `page` 从 **0** 开始，`size` 默认 10 |
| 状态值 | 大写英文枚举，与 01 文档状态机一致 |
| 字符编码 | UTF-8 |

### 1.4 错误码与典型文案

| code | 场景 | 文案示例 |
|---|---|---|
| 400 | 字段为空/格式错 | `收货人不能为空` / `收货人手机号格式不正确` |
| 400 | 业务规则拒绝 | `今日已签到` / `该码已被使用` / `库存不足` |
| 400 | 状态非法 | `订单状态不允许支付（幂等保护）` |
| 401 | 令牌缺失/无效 | `请先登录` / `管理员未登录或登录已过期` |
| 500 | 未预期异常 | `系统繁忙，请稍后重试` |

## 2. 客户端接口（`/api/**`）

### 2.1 会员 `MemberController`

#### API-01 登录 / 注册

```
POST /api/member/login        公开
```

| 参数 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `phone` | string | 是 | 11 位、以 1 开头 |
| `smsCode` | string | 是 | 演示环境固定 `123456` |

**响应** `data: { token, member, level, levelName, pointRate, discount }`

```json
{
  "code": 200,
  "msg": "操作成功",
  "data": {
    "token": "MBR-8f3a...",
    "member": { "id": 1, "phone": "13800001111", "nickname": "青果会员1111", "growth": 0.0, "points": 0 },
    "level": 0,
    "levelName": "注册会员",
    "pointRate": 1.0,
    "discount": 1.0
  }
}
```

**错误**：`验证码错误（演示环境固定为 123456）` · `手机号格式不正确`

> 新手机号自动注册，无需单独注册接口（U-01）。

#### API-02 当前会员信息

```
GET /api/member/me            需 MEMBER
```

**响应** `data: { member, level, levelName, pointRate, discount }`

#### API-03 积分流水

```
GET /api/member/points/logs?page=0&size=10     需 MEMBER
```

**响应**：Spring `Page<PointsLog>`，按 `createdAt` 倒序。`PointsLog` 字段：`id / memberId / type / amount / remark / createdAt`，`type ∈ CHECKIN|SCAN|EARN|REFUND_BACK|ADJUST`。

> ⚠️ 此接口必须保持 `content` 嵌套结构，H5 端直接消费 `res.data.content`。

#### API-04 每日签到

```
POST /api/member/checkin      需 MEMBER
```

**响应** `data: { points: 5 }`（本次发放值）
**错误**：`今日已签到`

#### API-05 扫码积分

```
POST /api/member/scan         需 MEMBER
```

| 参数 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `code` | string | 是 | 非空，须为已发码且未使用 |

**响应** `data: { points: 10 }`
**错误**：`防伪码不能为空` / `防伪码不存在，请核对` / `该码已被使用` / `今日扫码已达上限（20 包）`

### 2.2 商品 `ProductController`

#### API-06 商品列表

```
GET /api/products?category=&page=0&size=10     公开
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `category` | string | 否 | 分类名，空则查全部 |
| `page` / `size` | int | 否 | 默认 0 / 10 |

**响应**：`Page<Product>`，仅 `status=1`（上架），按 `sales` 倒序。
`Product` 字段：`id / name / category / subtitle / cover / sales / status / pointsFlag / createdAt`

#### API-07 商品详情

```
GET /api/products/{id}        公开
```

**响应** `data: { product, skus[] }`
`ProductSku`：`id / productId / spec / price / totalStock / lockedStock / skuCode`
**错误**：`商品不存在或已下架`

> 前端展示的"可售库存"需自行计算 `totalStock - lockedStock`，接口不返回该派生值。

### 2.3 购物车 `CartController`

#### API-08 购物车列表

```
GET /api/cart                 需 MEMBER
```

**响应** `data: CartItemVo[]`

```json
[
  {
    "cartId": 1, "skuId": 1, "productName": "经典桂子油槟榔",
    "spec": "10 包/袋", "cover": "/images/p1.png",
    "price": 29.90, "qty": 2, "onSale": true
  }
]
```

`onSale=false` 表示商品已下架或 SKU 已删除，前端应置灰。

#### API-09 加入购物车

```
POST /api/cart                需 MEMBER
```

| 参数 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `skuId` | long | 是 | 必须存在 |
| `qty` | int | 是 | 1 ≤ qty ≤ 999 |

**响应** `data: null`
**错误**：`SKU 不能为空` / `购买数量必须大于 0` / `单次加购数量不能超过 999` / `商品已下架，无法加入购物车`

> 同 SKU 再次加购为数量累加（C-01）。

#### API-10 修改购物车数量

```
PUT /api/cart/{cartId}        需 MEMBER
```

| 参数 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `qty` | int | 是 | > 0 为改数量，≤ 0 为删除该项 |

**错误**：`数量不能为空` / `无权操作`

### 2.4 订单 `OrderController`

#### API-11 创建订单

```
POST /api/orders              需 MEMBER
```

```json
{
  "lines": [{ "skuId": 1, "qty": 2 }],
  "receiver": "张三",
  "receiverPhone": "13800001111",
  "address": "湖南省长沙市岳麓区xx路 1 号"
}
```

| 参数 | 必填 | 校验 |
|---|---|---|
| `lines` | 是 | 非空；每项 `skuId` 必填、`qty > 0` |
| `receiver` | 是 | 非空 |
| `receiverPhone` | 是 | 11 位手机号格式 |
| `address` | 是 | 非空 |

**响应** `data: MallOrder`（含 `items[]`），状态 `WAIT_PAY`，`payDeadline = now + 15min`。

```json
{
  "orderNo": "QGJ20261022113045000123",
  "goodsAmount": 59.80, "discountAmount": 0.00, "freight": 8.00, "payAmount": 67.80,
  "status": "WAIT_PAY",
  "payDeadline": "2026-10-22T11:45:45.123456",
  "items": [{ "skuId": 1, "productName": "经典桂子油槟榔", "spec": "10 包/袋", "price": 29.90, "qty": 2, "payAmount": 59.80 }]
}
```

**错误**：`订单明细不能为空` / `收货人不能为空` / `收货人手机号格式不正确` / `收货地址不能为空` / `商品「xx」已下架` / `商品「xx 规格」库存不足`

> 库存预占与订单创建同一事务，任一明细不足则整单回滚（S-02）。

#### API-12 支付

```
POST /api/orders/{orderNo}/pay        需 MEMBER
```

**响应** `data: MallOrder`（`status=PAID`，含 `pointsEarned` / `growthEarned`）
**错误**：`无权操作该订单` / `订单状态不允许支付（幂等保护）` / `库存异常，请联系客服`

**副作用**：扣减库存、发放积分、累加成长值，三者与状态变更同事务。

#### API-13 取消订单

```
POST /api/orders/{orderNo}/cancel     需 MEMBER
```

**响应** `data: null`
**行为**：仅 `WAIT_PAY` 生效并释放库存；其他状态静默返回成功（幂等）。

#### API-14 确认收货

```
POST /api/orders/{orderNo}/confirm    需 MEMBER
```

**响应** `data: null`
**错误**：`订单状态不允许确认收货`

#### API-15 我的订单列表

```
GET /api/orders?status=&page=0&size=10        需 MEMBER
```

| 参数 | 说明 |
|---|---|
| `status` | 可选，`WAIT_PAY` / `PAID` / `SHIPPED` / `COMPLETED` / `CANCELED` / `AFTER_SALE`；空为全部 |

**响应**：`Page<MallOrder>`，按 `createdAt` 倒序，`items` 为嵌套数组。

### 2.5 售后 `AfterSaleController`

#### API-16 申请售后

```
POST /api/aftersale           需 MEMBER
```

| 参数 | 类型 | 必填 | 校验 |
|---|---|---|---|
| `orderItemId` | long | 是 | 必须属于当前会员的订单 |
| `type` | string | 是 | `REFUND_ONLY` / `RETURN_REFUND` |
| `qty` | int | 是 | 1 ≤ qty ≤ `购买数量 − 已售后数量` |
| `reason` | string | 是 | 非空 |
| `description` | string | 否 | 补充说明 |

**响应** `data: AfterSale`，`status=WAIT_AUDIT`，`refundAmount = 明细实付单价 × qty`

**错误**：`售后类型不合法（仅支持 REFUND_ONLY / RETURN_REFUND）` / `请填写售后原因` / `当前订单状态不可申请售后` / `已发货/已完成订单仅支持退货退款` / `售后数量不合法，最多可退 n 件`

**副作用**：累加 `orderItem.afterSaleQty`；若该明细已全部售后，订单状态置 `AFTER_SALE`。

#### API-17 我的售后列表

```
GET /api/aftersale/my?page=0&size=10          需 MEMBER
```

**响应**：`Page<AfterSale>`，按创建时间倒序。

#### API-18 填写退货物流

```
POST /api/aftersale/{id}/return-logistics     需 MEMBER
```

| 参数 | 类型 | 必填 |
|---|---|---|
| `logisticsNo` | string | 是 |

**响应** `data: null`，状态 `WAIT_RETURN → WAIT_RECEIVE`
**错误**：`退货物流单号不能为空` / `当前状态不可填写退货物流`

> H5 当前未提供该操作入口，接口已就绪（变更候选 C-06）。

| 参数 | 必填 | 说明 |
|---|---|---|

### 3.2 看板 `AdminDashboardController`

#### API-20 看板指标

```
GET /admin-api/dashboard      需 ADMIN
```

**响应**

```json
{
  "todaySales": 0,
  "waitShipOrders": 3,
  "waitAuditAfterSales": 1,
  "memberCount": 12,
  "lowStockSkuCount": 2
}
```

| 字段 | 口径 | 备注 |
|---|---|---|
| `todaySales` | 当日 PAID 及之后状态订单实付合计 | ⚠️ 恒为 0，待接支付流水表 |
| `waitShipOrders` | `status = PAID` 的订单数 | — |
| `waitAuditAfterSales` | `status = WAIT_AUDIT` 的售后数 | — |
| `memberCount` | 会员总数 | — |
| `lowStockSkuCount` | 可售库存 < 10 的 SKU 数 | 阈值 `LOW_STOCK_THRESHOLD` |

### 3.3 商品 `AdminProductController`

#### API-22 上下架

```
POST /admin-api/products/{id}/status          需 ADMIN
```

| 参数 | 类型 | 必填 | 校验 |

**响应** `data: null`

### 3.4 库存 `AdminStockController`

#### API-23 SKU 库存列表

```
GET /admin-api/skus           需 ADMIN
```

**响应** `data: ProductSku[]`（不分页，全量返回）

#### API-24 库存调整

| `reason` | string | 否 | 为空时留痕记"人工调整" |

**响应** `data: { totalStock, availableStock }`
**错误**：`调整数量不能为空` / `调整数量不能为 0` / `库存不足，无法扣减`

### 3.6 售后 `AdminAfterSaleController`

#### API-27 售后列表

```
GET /admin-api/aftersales?status=&page=0&size=10      需 ADMIN
```

**响应**：`TableDataInfo<AfterSale>`

#### API-28 审核

```
POST /admin-api/aftersales/{id}/audit         需 ADMIN
```

| 参数 | 类型 | 必填 | 说明 |
|---|---|---|---|
| `pass` | boolean | 是 | `true` 通过 / `false` 拒绝 |
| `rejectReason` | string | 否 | 拒绝时为空则落"不符合售后条件" |

**响应** `data: AfterSale`
- 通过 + `REFUND_ONLY` → `DONE`（退款 + 扣积分）
- 通过 + `RETURN_REFUND` → `WAIT_RETURN`
- 拒绝 → `REJECTED`

**错误**：`售后单状态不允许审核` / `售后单不存在`

#### API-29 确认收到退货并退款

```
POST /admin-api/aftersales/{id}/confirm-return        需 ADMIN
```

**响应** `data: AfterSale`（`status=DONE`）
**错误**：`售后单状态不允许确认收货`（仅 `WAIT_RECEIVE` 可操作）
**副作用**：模拟退款、回补库存、按比例扣回积分与成长值。

| `reason` | string | 否 | 流水备注 |

**错误**：`调整积分不能为空` / `调整积分不能为 0` / `积分不足，无法扣减`


## 5. 契约变更规则

1. **新增字段**：向后兼容，直接加，不需要动前端。
2. **删改字段 / 改结构**：必须先改本文档，再同步两端代码，最后跑 `05` 文档中的回归用例。
3. **`/api/**` 的分页结构不可随意改**：H5 依赖 `data.content`，改 `rows` 会让 H5 白屏。
4. **新增接口**：在本文件补编号（续 33 起）并在 01 文档补充需求编号，否则视为无来源的接口。
