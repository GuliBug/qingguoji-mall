# 04 · 开发规范与提交约定

> 目的：让三位协作者（前端 Web / 前端 H5 / 后端）在目录、命名、格式化、提交流程上保持统一，
> 降低「太乱」的维护成本。所有条目均已在当前工程中落地并验证。

---

## 1. 工程边界（前后端分离）

```
qingguoji-mall/
├── backend/          # Spring Boot 后端（独立 jar，8080）
├── frontend-web/     # Web 管理端（Vue3 + Element Plus，5173 / 生产静态资源）
├── frontend-h5/      # H5 客户端（Taro + Vue3，10086 / 生产静态资源）
├── deploy/           # 部署配置（Dockerfile / nginx / systemd / compose / 构建脚本）
├── docs/             # 原型稿 + 部署说明
└── specs/            # 本 SDD 文档集（需求→设计→规范→测试→部署→变更）
```
- 后端**不托管任何前端页面**（旧 `admin.html` 已删除）。
- 前后端通过 HTTP 接口契约解耦：客户端 `/api/**`，管理端 `/admin-api/**`。

## 2. 后端规范（Java / Spring Boot）

### 2.1 目录分层（若依风格）
```
com.qingguoji.mall
├── common/           # 通用：AjaxResult / TableDataInfo / ServiceException / BaseController / Constants / HttpStatus / StringUtils
├── framework/        # 框架：TokenService / LoginInterceptor / @RequireLogin / WebMvcConfig / OrderTimeoutTask / DemoDataInitializer
└── mall/             # 业务
    ├── controller/ + controller/admin/   # 接口层（仅做参数接收与响应包装）
    ├── domain/ + dto/ + vo/              # 实体 / 入参 / 出参
    ├── repository/                      # Spring Data JPA 仓储
    └── service/ + service/impl/          # 业务逻辑（禁止在 Controller 写业务）
```

### 2.2 命名约定
- 接口返回统一 `AjaxResult<T>`（客户端）或 `TableDataInfo<T>`（管理端列表）。
- 业务异常统一抛 `ServiceException("文案")`，由 `GlobalExceptionHandler` 兜底为 `{code:500, msg}`。
- 鉴权：Controller 类标注 `@RequireLogin(LoginType.ADMIN | MEMBER)`，禁止在方法里手写 token 校验。
- 分页：客户端保持 Spring `Page`（前端吃 `content/totalElements`）；管理端列表用 `getDataTable(...)` 输出 `{total, rows}`。

### 2.3 代码格式化（强制）
- 工具：**Spotless + google-java-format（AOSP，4 空格缩进）**。
- 配置：已在 `pom.xml` 接入 `spotless-maven-plugin`。
- 命令：
  ```bash
  mvn spotless:apply     # 格式化
  mvn spotless:check     # 校验（mvn verify 时自动执行，不合规则构建失败）
  ```
- 编辑器：工程根 `backend/.editorconfig` 已定义 4 空格、LF、UTF-8。

## 3. Web 管理端规范（Vue3 / Element Plus）

### 3.1 目录（若依 ruoyi-ui 风格）
```
src/
├── api/        # 一个业务一个文件（login / product / order / ...）
├── components/ # Pagination / RightToolbar / DictTag
├── directive/  # v-hasRole / v-hasPermi
├── layout/     # Sidebar / Navbar / Breadcrumb / TagsView / AppMain
├── plugins/    # cache / modal
├── router/     # constantRoutes（静态）+ asyncRoutes（动态）
├── store/      # pinia：user / app / permission / settings
├── utils/      # request（axios 拦截器）/ auth / validate / ruoyi / format / dict
└── views/      # 页面（login / dashboard / product / stock / order / aftersale / member）
```

### 3.2 代码格式化与校验（强制）
- Lint：**ESLint 9（flat config）+ eslint-plugin-vue**。
- Format：**Prettier**（配置文件 `.prettierrc.json`，2 空格、LF、单引号、无分号）。
- 命令：
  ```bash
  npm run lint           # ESLint 检查（--fix 可自动修复）
  npm run format         # Prettier 写格式化
  npm run format:check   # Prettier 校验（CI 用）
  ```

## 4. H5 客户端规范（Taro / Vue3 / TS）

### 4.1 约定
- 所有后端调用**必须经 `src/api.ts`**，禁止页面内直接 `Taro.request`。
- 接口返回判断：`res.code === 200` 成功，否则 `res.msg` 提示。
- 页面状态用 `<script setup>` 的 `ref` 局部管理；登录态走 `Taro.setStorageSync`。
- 新增页面：先在 `app.config.ts` 的 `pages` 注册，再建 `pages/xxx/index.vue`。

### 4.2 校验
- TypeScript 类型检查：`npm run build:h5` 通过即代表类型/编译无误。
- 建议后续补 `@tarojs/eslint-config` + Prettier（当前未强制）。

---

## 5. 提交约定

- 单一职责：一次提交聚焦一个模块（如「重构后端管理端接口为若依风格」）。
- 提交信息建议格式：`[模块] 动作：说明`，例如 `[backend] refactor: 拆分 MallService 为 6 个领域服务`。
- 格式化前置：提交前确保 `mvn spotless:check`（后端）与 `npm run lint`（Web）零报错。
- 不提交 `dist/`、`node_modules/`、`target/`、本地 `*.log`（已被各 `.gitignore` 覆盖）。
- 密钥/内网地址不入库：生产配置通过 `deploy/.env`（不跟踪）或环境变量注入。
